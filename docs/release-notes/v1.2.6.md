proj-rs is a Rust port of [PROJ](https://github.com/OSGeo/PROJ) 9.9.0: projections, pipelines,
the ISO 19111 CRS model and the operation factory, with PROJ's `proj.db` embedded. 1.2.6 keeps the
API of 1.2.5; the full list is in
[`CHANGELOG.md`](https://github.com/RandazzoMaxime/proj-rs/blob/v1.2.6/CHANGELOG.md).

proj-rs is an independent project. It is not affiliated with, endorsed by or maintained by the
PROJ project, its developers or OSGeo.

## What is new in 1.2.6

**`+datum=` no longer hides the ellipsoid keys.** As in PROJ, an earlier `+ellps` and the size
and shape keys (`+R`, `+a`, `+b`, `+rf`, `+f`, `+e`, `+es`) now override the ellipsoid of the
datum. `+proj=merc +datum=WGS84 +R=6370000` is a sphere again: it was WGS 84, up to 23 km off at
45°N. `+datum=WGS84 +a=6378137 +b=6356752.314` gives the `unknown` datum PROJ 9.9.0 builds from
the numbers. This is the SRS GMT writes for its grids.

**Grids looked up as PROJ does.** A context keeps the answers of its grid lookups in PROJ's cache
(128 keys). A grid that did not open is not tried again while its key is kept. The candidates of
`proj_create_operations` and `proj_create_crs_to_crs` are sorted and kept by the same rules as
PROJ when the network is on. The `Cannot open <url>` lines reach the logger of the context, once
per open, as with PROJ. Seven C API constructors now give PROJ's object, error code and message
for NULL or wrongly typed arguments.

**Smaller and lighter.** The embedded `proj.db` is stored compressed, page by page, and has no
triggers. The binary is 7.6 MB smaller and creating a transform peaks at about 2.5 MiB less. The
first creation in a process takes about 9 ms more; conversions do not change. See
[`docs/PORTING-memory.md`](https://github.com/RandazzoMaxime/proj-rs/blob/v1.2.6/docs/PORTING-memory.md).

**AVX-512, as an option.** On x86-64, the new `avx512` cargo feature (off by default, Rust 1.89 or
later) runs the batch kernels 8 points at a time. On a Xeon 6985P-C, batches are 1.1 to 1.8
times faster than the AVX2 path. Point by point calls do not change. See
[`docs/PORTING-simd.md`](https://github.com/RandazzoMaxime/proj-rs/blob/v1.2.6/docs/PORTING-simd.md).

**Tried in place of libproj in real software.** The C library ran under the test suites of GRASS
GIS, PostGIS, PDAL, pyproj, GMT, R (sf, terra), SpatiaLite, libgeotiff and georust/proj, once with
PROJ 9.9.0's libproj and once with proj-rs. Every test has the same outcome with both libraries,
except 4 GMT tests that make no libproj call: two change outcome under load, and two change
between two runs with the same library, because of a race in GMT's history file. Each run proves
which libproj it loaded. The results are in the
[README](https://github.com/RandazzoMaxime/proj-rs/blob/v1.2.6/README.md#tried-as-libproj-in-real-software).
For example, PDAL passes 142 of 142 tests with both, and pyproj 1044 of 1045 (the last test is
disabled in pyproj's source).

The archives are the same six platforms as 1.2.5, with `SHA256SUMS`.

proj-rs is a Rust port of [PROJ](https://github.com/OSGeo/PROJ) 9.9.0: projections, pipelines,
the ISO 19111 CRS model and the operation factory, with PROJ's `proj.db` embedded. 1.2.5 keeps the
API of 1.2.0; the full list is in
[`CHANGELOG.md`](https://github.com/RandazzoMaxime/proj-rs/blob/v1.2.5/CHANGELOG.md).

## What is new in 1.2.5

**A fast batch path on ARM.** `convert_array`, `project_array` and the `*_batch` functions now run
four points at a time with NEON on aarch64 (Apple silicon, Linux ARM), as they already did with
AVX2 on x86-64. `batch_path()` gives `neon`. The code is the same on both architectures: `V4` has
a second realisation on two `float64x2_t` registers, built on the safe wrappers of `pulp`, so the
repository still has no `unsafe` outside `capi/`. There is no `libmvec` and no Accelerate.

Measured on the CI machines, the portable path of 1.2.0 against 1.2.5, in turn on the same
machine:

| Case (batch) | Apple M1 | Neoverse N2 (Linux ARM) |
|---|---:|---:|
| UTM 31, forward / inverse | 1.7× / 3.0× | 1.6× / 2.0× |
| Lambert-93, forward / inverse | 2.1× / 2.4× | 1.6× / 2.1× |
| Web Mercator, forward / inverse | 2.4× / 4.1× | 1.8× / 2.1× |
| `convert_array` EPSG:2154 to EPSG:32631 | 2.5× | 2.0× |

Point by point calls (`forward`, `inverse`) do not change.

**Same bits as AVX2, where it can be checked.** The 11 vector math functions give the digests of
the AVX2 path on Apple silicon and on Linux ARM. The kernels (equatorial `laea`, `somerc`,
`sterea`, `cart`, `helmert`) do on Linux ARM. macOS and Windows are left out for the kernels: the
set-up of a projection calls the C library of the platform, which rounds differently.

**Known on Linux ARM.** Seven near-antipodal geodesic inverse lines of the parity suite differ from
PROJ on real aarch64 glibc, as some already do with Apple's library. They are named in
`tests/parity/geod/known-linux-aarch64.tsv`.

The archives are the same six platforms as 1.2.0, with `SHA256SUMS`. Details:
[`docs/PORTING-simd.md`](https://github.com/RandazzoMaxime/proj-rs/blob/v1.2.5/docs/PORTING-simd.md).

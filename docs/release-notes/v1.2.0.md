proj-rs is a Rust port of [PROJ](https://github.com/OSGeo/PROJ) 9.9.0: projections, pipelines,
the ISO 19111 CRS model and the operation factory, with PROJ's `proj.db` embedded. 1.2.0 keeps the
API of 1.1.0 and adds to it; the full list is in
[`CHANGELOG.md`](https://github.com/RandazzoMaxime/proj-rs/blob/v1.2.0/CHANGELOG.md).

## What is new in 1.2.0

**Nine real clients, the same results.** Their own test suites were run twice, once on libproj
9.9.0 and once on proj-rs. 1.1.0 had pyproj, QGIS and GDAL; 1.2.0 adds six:

| Client | Result |
|---|---|
| SpatiaLite 5.1.0 | 104 of 108 tests on both sides, 0 logs that differ |
| georust/proj 0.31.0 | 26 of 26 tests and 24 of 24 examples on the C library; 24 of 26 on the Rust facade (one ignored, one deliberate difference) |
| libgeotiff 1.7.4 | 0 lines of `listgeo` and `geotifcp` that differ |
| PDAL 2.10.2 | 140 of 142; the two tests that read remote files fail on both |
| PostGIS 3.6.4 | 247 of 247 |
| GRASS 8.5.0 | the same result for each of 818 tests |

Each has its script in `tools/clients/` and its sheet in `docs/CLIENTS-<name>.md`. Every
difference they found is fixed and compared with libproj by `capi/tests/run.sh`.

**WKT and PROJ strings are read as PROJ reads them.**

- The grammar errors of a WKT are PROJ's, byte for byte: the bison grammars of its WKT1 and WKT2
  parsers are ported. There is no difference on the 21,342 WKT of the EPSG database and on 64,703
  malformed ones. A message that cuts a multi-byte character keeps PROJ's bytes.
- A CRS read back from its WKT gives PROJ's PROJ string for all 13,719 EPSG CRS: polar axes, the
  WGS 84 ensemble, Krovak. The 541 EPSG operations with a grid, such as vertical offsets and
  geoid models, export to a PROJ string too.
- `proj_create` refuses at creation what `pj_init` refuses, with PROJ's error code and text, and
  reads a WKT before a PROJ string. `proj_create_from_wkt` gives PROJ's `validateParameters`
  warnings.

**Fixed.** `projinfo` and the identification of a CRS panicked on a name with an accented
character, because a name was cut inside the character.

## Downloads

| Platform | `-cli` archive | `-libproj` archive |
|---|---|---|
| `linux-x86_64` (glibc 2.35 or newer) | yes | yes |
| `linux-aarch64` (glibc 2.35 or newer) | yes | yes |
| `linux-x86_64-musl` (static, any Linux) | yes | no |
| `macos-arm64` | yes | yes |
| `macos-x86_64` | yes | yes |
| `windows-x86_64` (Visual C++ runtime) | yes | yes |

- `proj-rs-1.2.0-<platform>-cli` (`.tar.gz`, `.zip` on Windows) holds `bin/proj-rs` and the tool
  names (`cct`, `cs2cs`, `proj`, `invproj`, `geod`, `invgeod`, `gie`, `projinfo`).
- `proj-rs-1.2.0-<platform>-libproj` holds the C library under the names of libproj 9.9.0,
  `include/*.h`, `lib/pkgconfig/proj.pc`, `lib/cmake/proj/` and `share/proj/proj.db`.

Each archive holds a `README.txt`, the `LICENSE` and `NOTICE.md`.

**Verify the downloads.** `SHA256SUMS` lists every archive:

```sh
grep proj-rs-1.2.0-linux-x86_64-cli.tar.gz SHA256SUMS | sha256sum --check          # Linux
grep proj-rs-1.2.0-macos-arm64-cli.tar.gz SHA256SUMS | shasum -a 256 --check       # macOS
```

On Windows, run `Get-FileHash <archive>` and compare the result with the line of `SHA256SUMS`.

## For Rust projects

The crates are not on crates.io yet; use them from git:

```toml
[dependencies]
proj-rs = { git = "https://github.com/RandazzoMaxime/proj-rs", tag = "v1.2.0" }
```

## What is not in this release

- **No network in the binaries.** The archives are built with the default features: no grid
  download, no `projsync`, no TLS library. Build from source with `--features network` for them.
- **No grids.** The grid files are at <https://cdn.proj.org>.
- **Not signed.** The Windows and macOS binaries carry no code signing or notarization.
- **No GPU backend.** It is still an open pull request.

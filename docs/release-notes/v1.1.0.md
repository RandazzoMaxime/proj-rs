proj-rs is a Rust port of [PROJ](https://github.com/OSGeo/PROJ) 9.9.0: projections, pipelines,
the ISO 19111 CRS model and the operation factory, with PROJ's `proj.db` embedded. 1.1.0 keeps the
API of 1.0.0 and adds to it; the full list is in
[`CHANGELOG.md`](https://github.com/RandazzoMaxime/proj-rs/blob/v1.1.0/CHANGELOG.md).

## What is new in 1.1.0

**The C library runs real clients.** Their own test suites were run twice, once on libproj 9.9.0
and once on proj-rs:

- **pyproj 3.8.0**: every test that passes on libproj passes on proj-rs
  ([`docs/CLIENTS-pyproj.md`](https://github.com/RandazzoMaxime/proj-rs/blob/v1.1.0/docs/CLIENTS-pyproj.md),
  `tools/clients/pyproj.sh` reruns it);
- **QGIS 3.34.4** (its Python tests): the same result as libproj, test by test;
- **GDAL 3.13.3** (its `osr` tests): the same, except three tests that point `PROJ_DATA` or the
  search path at another `proj.db`. proj-rs embeds its database; this difference is deliberate
  ([`docs/PORTING-database-open.md`](https://github.com/RandazzoMaxime/proj-rs/blob/v1.1.0/docs/PORTING-database-open.md)).

About seventy fixes of the C API got there. Each is compared with libproj 9.9.0 by the C tests in
`capi/tests/run.sh`. Among them:

- `proj_create` reads any object: URN, WKT and PROJJSON of operations, datums, ensembles,
  ellipsoids and coordinate systems. Every object exports to WKT and PROJJSON.
- PROJ strings are read as PROJ reads them: words, quoted values, angles in degrees, minutes and
  seconds, `+init=` files and sections.
- `proj_create_crs_to_crs` builds the `ONLY_BEST`, `AUTHORITY`, area-of-interest and epoch options.
- `proj_trans` logs PROJ's error line for a refused point.

**More of the C API.** `geodesic.h` and its 21 `geod_*` functions; `pkg-config proj` and CMake's
`find_package(PROJ 9 CONFIG)` find the library; the archive carries `share/proj/proj.db` for the
clients that look for the file.

**For Rust code:**

- `Transformer` is `Send + Sync`: several threads convert through one transformer.
- `Transformer` builds its candidates at their first use. On a pair with grids, a dev build went
  from 11.8 s to 0.55 s.
- A stable CRS catalogue and the database metadata (`Context::crs_catalog()`,
  `Context::database_metadata()`).
- A context that reads nothing from the machine (`Context::builder().hermetic()`).
- Karney's geodesic library in Rust, with the polygon area.
- `Proj::convert_iter`.

**Less `unsafe`.** Outside the C API, one file is left (the 48 `unsafe` of `src/projdb_exe.rs`),
and a test refuses any new one.

**Back to Rust 1.83.** The minimum supported Rust version is 1.83 again. The release is built with
1.100.

## Downloads

| Platform | `-cli` archive | `-libproj` archive |
|---|---|---|
| `linux-x86_64` (glibc 2.35 or newer) | yes | yes |
| `linux-aarch64` (glibc 2.35 or newer) | yes | yes |
| `linux-x86_64-musl` (static, any Linux) | yes | no |
| `macos-arm64` | yes | yes |
| `macos-x86_64` | yes | yes |
| `windows-x86_64` (Visual C++ runtime) | yes | yes |

- `proj-rs-1.1.0-<platform>-cli` (`.tar.gz`, `.zip` on Windows) holds `bin/proj-rs` and the tool
  names (`cct`, `cs2cs`, `proj`, `invproj`, `geod`, `invgeod`, `gie`, `projinfo`).
- `proj-rs-1.1.0-<platform>-libproj` holds the C library under the names of libproj 9.9.0,
  `include/*.h`, `lib/pkgconfig/proj.pc`, `lib/cmake/proj/` and `share/proj/proj.db`.

Each archive holds a `README.txt`, the `LICENSE` and `NOTICE.md`.

**Verify the downloads.** `SHA256SUMS` lists every archive:

```sh
grep proj-rs-1.1.0-linux-x86_64-cli.tar.gz SHA256SUMS | sha256sum --check          # Linux
grep proj-rs-1.1.0-macos-arm64-cli.tar.gz SHA256SUMS | shasum -a 256 --check       # macOS
```

On Windows, run `Get-FileHash <archive>` and compare the result with the line of `SHA256SUMS`.

## For Rust projects

The crates are not on crates.io yet; use them from git:

```toml
[dependencies]
proj-rs = { git = "https://github.com/RandazzoMaxime/proj-rs", tag = "v1.1.0" }
```

## What is not in this release

- **No network in the binaries.** The archives are built with the default features: no grid
  download, no `projsync`, no TLS library. Build from source with `--features network` for them.
- **No grids.** The grid files are at <https://cdn.proj.org>.
- **Not signed.** The Windows and macOS binaries carry no code signing or notarization.
- **No GPU backend.** It is still an open pull request.

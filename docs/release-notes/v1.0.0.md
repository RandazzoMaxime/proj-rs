proj-rs is a Rust port of [PROJ](https://github.com/OSGeo/PROJ) 9.9.0: projections, pipelines,
the ISO 19111 CRS model and the operation factory, with PROJ's `proj.db` embedded. 1.0.0 is the
first release with a stable API.

## What is in 1.0.0

**The same numbers as PROJ 9.9.0.** The port is checked against PROJ's own tests: the `gie`
suite, the C++ unit tests ported one `TEST()` at a time, the cases of the command-line tools, and
about 4000 conversions compared with the reference `cs2cs`. 9,188 of 9,188 tracked cases pass. The
results equal PROJ's to 1 µm on linear coordinates and 1e-11 degree on angles, not bit for bit
(the rule: [`docs/PARITY.md`](https://github.com/RandazzoMaxime/proj-rs/blob/v1.0.0/docs/PARITY.md)).
An unknown projection, an unknown method or a missing grid is an error at creation, never a
coordinate.

**Three facades over one engine** ([`docs/API-v1.md`](https://github.com/RandazzoMaxime/proj-rs/blob/v1.0.0/docs/API-v1.md)):

- the native Rust API (`proj-rs`): `Context`, `Crs`, `Transformer`, `Point`, results and enums
  instead of error codes and NaN sentinels;
- a drop-in for the georust [`proj`](https://github.com/georust/proj) crate (`proj-rs-georust`,
  the library is still named `proj`): georust's own 0.31 unit tests and documentation examples run
  against it;
- the C API: the `proj.h` of PROJ 9.9.0, the same 292 functions, signatures and structures, as a
  replacement for `libproj` 9.9.0 (`libproj.so.25`, `libproj.25.dylib`, `proj.dll`). The C tests
  of PROJ run against it in CI.

**Self-contained.** `proj.db` is inside the library and the executable: EPSG codes and the
operation catalogue need no PROJ install and no `PROJ_DATA`. No TLS library is built or linked by
default.

**Command-line tools in one executable.** `proj-rs` is `cct`, `cs2cs`, `proj`, `invproj`, `geod`,
`invgeod`, `gie` and `projinfo`; it runs the tool it is started under (`cs2cs` is a link to it)
or the tool named by its first argument (`proj-rs cs2cs ...`). It is 17.7 MiB; the eight separate
programs would be 137.8 MiB, each carrying `proj.db`.

**Speed, size and memory** (Linux x86-64; the measurements and the method are in the
[README](https://github.com/RandazzoMaxime/proj-rs/blob/v1.0.0/README.md#how-fast) and
[`docs/BENCHMARK.md`](https://github.com/RandazzoMaxime/proj-rs/blob/v1.0.0/docs/BENCHMARK.md)):

- On a 4-vCPU cloud VM (Intel Xeon at 2.10 GHz), one core, proj-rs is 2.8× faster than PROJ 9.9.0's
  `libproj` on average over ten conversions (geometric mean; faster in every case, from 1.1× to
  6.9×): 1.9× one point at a time, 4.2× on a slice of points, with the AVX2 batch path. This is
  one machine; the ratios on another CPU will differ.
- Peak memory is under PROJ's in the five scenarios measured: creating the EPSG:4326 to EPSG:2154
  transform peaks at 12.1 MiB against 14.8 MiB (1.2× less).
- A Rust program with proj-rs is 17.1 MiB with `proj.db` included (10.1 MiB of it), against 18.6 MiB
  for a C program with PROJ 9.9.0 built as in the speed comparison.

## Downloads

Two archives per platform. `<platform>` is `linux-x86_64`, `macos-arm64`, `macos-x86_64` or
`windows-x86_64`.

| Archive | Contents |
|---|---|
| `proj-rs-1.0.0-<platform>-cli` (`.tar.gz`, `.zip` on Windows) | `bin/proj-rs` and the tool names (links to it; `.cmd` launchers on Windows, with `link-tools.ps1` to make hard links) |
| `proj-rs-1.0.0-<platform>-libproj` | the C library under the names of libproj 9.9.0 (`lib/libproj.so.25`, `libproj.so`, `libproj.a`; `libproj.25.dylib`, `libproj.dylib`, `libproj.a`; `bin/proj.dll`, `lib/proj.lib`) and `include/*.h` |

Each archive holds a `README.txt` (install, where to put grids), the `LICENSE` and `NOTICE.md`.
The Linux binaries are built on Ubuntu 22.04 and need glibc 2.35 or newer. The Windows binaries
need the Visual C++ runtime.

**Verify the downloads.** `SHA256SUMS` lists every archive:

```sh
grep proj-rs-1.0.0-linux-x86_64-cli.tar.gz SHA256SUMS | sha256sum --check          # Linux
grep proj-rs-1.0.0-macos-arm64-cli.tar.gz SHA256SUMS | shasum -a 256 --check       # macOS
```

On Windows: `Get-FileHash <archive>` and compare with the line of `SHA256SUMS`. The line
for an archive is `<sha256>  <file name>`; the check passes when the program prints `OK`.

## For Rust projects

There is no binary to download: add the crates. `proj-rs` and `proj-rs-georust` are not on
crates.io yet; until they are, use them from git:

```toml
[dependencies]
proj-rs = { git = "https://github.com/RandazzoMaxime/proj-rs", tag = "v1.0.0" }
```

The minimum supported Rust version is **1.100**.

## What is not in this release

- **No network in the binaries.** The archives are built with the default features: no grid
  download over HTTP(S), no `projsync`, no TLS library. A missing grid is an error; put your grids
  in the places listed in the `README.txt` of the archive, or build from source with
  `--features network`.
- **No grids.** `proj.db` is inside, the grid files (`.tif`, `.gsb`, ...) are not: they are published
  at <https://cdn.proj.org>.
- **Not on crates.io yet.** The crates are ready to publish; the first publication comes later.
- **Not signed.** The Windows and macOS binaries carry no code-signing or notarization. Windows
  SmartScreen and macOS Gatekeeper may warn on a download made with a browser (on macOS, `xattr
  -d com.apple.quarantine <file>` or unpack with `tar` in a terminal).
- **No `proj.pc` and no CMake package file** with the C library: pass the include and library
  paths to your build.
- **The optimisation work comes after v1:** wider SIMD and GPU backends are not part of this
  release.

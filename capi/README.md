# proj-rs-capi

The `proj.h` of PROJ 9.9.0 on the proj-rs engine. `include/` holds the headers of PROJ, byte for
byte; the library exports the 292 functions of `proj.h` and `pj_release` with their names,
signatures and structures. All 292 are implemented. It also exports the geodesic API of PROJ,
`geodesic.h` and its 21 `geod_*` functions, over the Rust port of `geodesic.c`
(`capi/src/geodesic.rs`). `docs/API-v1.md` § C and « Écarts du lot 2 » say what differs from PROJ.

```bash
capi/tests/dist.sh --release     # target/capi-dist/{lib,include}: libproj.so.25, libproj.so, libproj.a
capi/tests/run.sh                # the C tests of PROJ against the library (see tests/README.md)
```

| Path | What |
|---|---|
| `include/` | `proj.h`, `proj_constants.h`, `proj_experimental.h`, `proj_symbol_rename.h` of PROJ 9.9.0 |
| `src/ffi.rs` | the types of `proj.h`, generated by bindgen, with compile-time layout assertions |
| `src/util.rs` | the unsafe edge: C strings, pointers, the panic guard |
| `src/context.rs`, `pj.rs`, `trans.rs`, `misc.rs`, `info.rs` | contexts, errors, log, creation, transformation, angles, distances, information |
| `src/iso.rs`, `inspect.rs`, `crsops.rs`, `creators.rs`, `ops.rs`, `list.rs` | ISO 19111 objects and the operation factory |
| `src/db.rs`, `dblists.rs`, `network.rs` | the database, its lists, network and grid cache |
| `src/conversions.rs`, `conversion_support.rs`, `constructors.rs` | the `proj_create_conversion_*` (generated by `tools/gen_conversions.py`) and the other constructors of CRS and operations |
| `src/lists.rs`, `lists_data.rs`, `callbacks.rs` | the static `proj_list_*` tables (data generated by `tools/gen_lists.py`), the file and network callbacks |
| `tools/` | `gen_abi_check.py`, `gen_conversions.py`, `gen_lists.py`, and `proj_h_functions.rs.txt` (the signatures they read) |
| `tests/` | the C tests of PROJ and their scripts |

The generated files are `src/conversions.rs`, `src/lists_data.rs` and `tests/abi_layout.c`; run
the tool, then `cargo fmt`.

Every entry point runs under `util::guard`: a panic becomes the failure value of the function and
never crosses the C boundary. The exported functions are safe Rust functions over raw pointers;
the C contract (a valid pointer or `NULL`) is relied on in `util.rs` only, where each `unsafe`
block says why it holds.
